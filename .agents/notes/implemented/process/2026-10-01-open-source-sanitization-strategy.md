# Agent Note: 开源发布前敏感信息脱敏与本地记忆保留策略

Status: implemented

## Problem

PProxy 作为一个开源出海代理项目，在日常迭代、压测和线上分布式部署运维中，积累了丰富的架构决策记录（`.agents/notes/`）与真实运维稳定性报告（`docs/ops/stability-report-2026-09-29.md`）。这些文档中记录了真实的内部 Tailscale 节点 IP（如 `100.95.193.103`、`100.105.241.39` 等）、公网 VPS 出口 IP（`192.210.231.8`）以及内部使用的中继/网关公网域名（`*.ponygo.fun`）。

直接在源码库中永久修改或清除这些信息会破坏“项目记忆”：
1. 开发者和运维人员在本地排障时无法对照真实节点的监控与日志历史；
2. 历史压测数据报告失去端到端复核对照的基准。

然而，在对外公开开源或发布版本产物时，上述内部基础设施特征属于敏感信息，不应直接暴露到公网社区，需要一套轻量、自动化且不破坏本地工作区记忆的发布态脱敏机制。

## Decision

我们确立了**“本地工作区保留真实记忆，发布打包阶段自动化脱敏”**的治理策略，并实现如下工程设施：

1. **确立标准 RFC 规范映射表**：
   - 内部 Tailscale 虚拟网 IP 映射为 RFC 6598 规定的 CGNAT 保留地址（`100.64.0.x`）；
   - 真实 VPS 出口 IP 映射为 RFC 5737 规定的文档测试公网地址（`198.51.100.8`）；
   - 私有中继与更新发布域名（`*.ponygo.fun`）统一映射为 RFC 2606 示例域名（`*.example.com`）。
2. **实现专用发布脱敏工具** `scripts/sanitize-for-release.py`：
   - 支持 `--check`（只读检测模式，检测未脱敏特征并统计，非零退出码支持 CI 门禁）；
   - 支持 `--in-place`（原地替换模式，供打包构建发布分支或发布归档包时调用）；
   - 支持 `--target-dir` 指定脱敏范围，默认覆盖 `docs/`、`.agents/notes/` 与 `README*.md`。
3. **在发布运维文档建立门禁**：
   - 在 `docs/ops/DEPLOY.md` 中增加「开源发布前脱敏规范与检查清单」，明确开源同步与打包前必须执行 `python3 scripts/sanitize-for-release.py --check`。

## Alternatives considered

1. **直接全局搜索并永久覆写 Git 历史中的所有敏感信息**：
   - *劣势*：会导致本地历史排障记录断裂，开发人员无法排查线上既有节点日志，且重写 git 历史（filter-repo）在多人协作下侵入性过高。
2. **使用 Git Clean/Smudge Filter**：
   - *劣势*：配置依赖开发机全局 `.gitattributes` 与 local git config，在新克隆环境容易因漏配 filter 导致未脱敏提交直接外泄，不如显式的发布脚本和 CI 门禁可靠。
3. **人工每次发布前手动逐个文件核对修改**：
   - *劣势*：极易疏漏，尤其随着 `.agents/notes/` 和压测日志的增多，人工核对成本过高。

## Consequences

- 本地仓库与日常提交保持真实信息不变，排障日志与节点配置完全吻合，项目记忆得以完整保留；
- 开源发布流程中获得确定性的自动化工具支持，杜绝生产拓扑信息向公网开源社区意外泄露。
