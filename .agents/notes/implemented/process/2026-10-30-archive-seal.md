# Agent Note: 归档封印——用 SHA256 清单把「archived/ 不该变」变成非零退出命令

Status: implemented

## Problem

`archived/` 的语义是「曾经落地、后被取代」的历史快照（`.agents/notes/README.md` 四态定义）。
在此之前它是**零归档 + 无封印**（2026-10-30 治理审查 #12：`archived/` 只有 AGENTS.md、无哈希记录）：
任何人都能顺手改一行、删一段，让归档与当下的决策对不上，而读者无从发现——
"归档即冻结"如果只写在文档里，它就不是承诺，是礼貌。

## Decision

新增归档封印门 `.meta/gates/archive-seal.sh`，把冻结变成一条会非零退出的命令：

1. **判据形态**：`archived/` 下每个文件的 sha256 清单落 `.agents/notes/archived/SHA256SUMS`
   （路径相对仓库根）。`--check` 判三件事：①清单内条目哈希是否仍一致（改写 → 1）；
   ②清单内文件是否还在（删除/改名 → 1）；③目录里是否有清单外文件（未封印的新条目 → 1）。
   `--write` 按当前内容重建清单（含新增、剔除已删）。
2. **退出码契约**：0 放行 / 1 不一致 / 2 环境或用法错误（缺清单、目录不存在、`sha256sum` 缺失、
   未指定模式）。**缺清单时 exit 2 而不是 0**——没有基准时的"通过"是假绿。
3. **自证能力**：仓库根由脚本自身位置推导（`dirname $0/../..`），并支持 `--root DIR`；
   因此在检出镜像里 `cd <mirror> && bash .meta/gates/archive-seal.sh --check` 与真仓同判据，
   不需要绑定绝对路径，也不需要 git。依赖只有 `find` / `sort` / `sha256sum` / `awk` / `sed`。
4. **接线**（`.meta/gates/instance-commitments.md` 第 5 条）：
   `.github/workflows/ponygo-governance.yml` 一步（全仓兜底）+ `.githooks/pre-push`（秒级、推送前）；
   pre-commit 不跑它——归档动作是低频事件，没必要占提交路径的预算。
5. **封印纪律**：`--write` 只在**归档动作的同一提交**里执行。归档动作本身仍是 write-adr 的
   「三件事同一次变更」：移动文件到 `archived/` + 改 `Status:` + 把时代标题改写为冻结原貌。

**负样本自检**：`.meta/gates/archive-seal.spec.sh` 覆盖改写/删除/未封印/缺清单/缺模式/越界路径
六种拒绝，外加"封印后立即校验放行"的回环与真仓放行——恒拒绝或恒放行都会被抓出来。

## Alternatives considered

- **只靠 git 历史（`git log --follow` + review）**：否决。git 记录"变了什么"，不判定"不该变"；
  `rebase`/`amend`/`filter-repo` 都能无声改写，且"这条历史条目变了没"要人肉比对。
- **只靠 review，不加脚本**：否决。没有退出码的承诺会在第一次赶工时消失；本仓已有
  same-commit 欠账的实证（审查 #8）。
- **清单放在 `archived/` 之外（如 `.meta/archive.sha256`）**：否决。封印与内容分离后，
  移动/复制归档目录就可能带着旧清单一起走，而"漏带清单"本身不再是一次可见的变更；
  放在同目录里，任何归档改动都必须显式带上清单更新。
- **每次 CI 重算全树哈希**：否决。全树哈希在 8MB/500 文件的仓里也要秒级，但它保护的是
  "所有文件都不该变"——那不是事实（活动树每天都在变）。封印面只覆盖真正冻结的 `archived/`。
- **用 `git hash-object` 代替 `sha256sum`**：否决。封印要能在非 git 检出（导出的 tar、镜像副本、
  归档备份）里自证；`sha256sum` 是 POSIX 工具集的通用面。

## Consequences

- 归档一旦封印，任何内容改动都会在 CI 与 push 前红；"确实该改"的路径只有一条：
  `--write` 重建清单并同提交，这本身就是一次可见的历史修订动作。
- 封印**不防恶意**（能改内容的人也能改清单），也不证明封印时内容是对的——它防的是
  无意的漂移与"顺手改一行"。这两个边界写进脚本头部，避免被读成"归档已经不可篡改"。
- `archived/` 目前只有 `AGENTS.md`（零归档条目）时清单也能工作（1 条），
  第一次真正归档时要在同提交跑 `--write`——否则新条目会以"未封印"被拒。
- 新增一类冻结面（例如将来冻结 `docs/architecture/decisions/`）时，优先复用本门的
  `--root` + 目录参数化能力，而不是再写一个同构脚本（P9：一份判据一份实现）。
