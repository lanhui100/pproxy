# Agent Note: 可观测性四维暂不接入（observe 声明维持缺失，属显式决定）

Status: implemented

## Problem

治理侧一直有一个「看起来是遗漏、其实没人下过判断」的缺口：`ponygo observe status` 报
`声明: 缺失`、`ponygo observe audit` 判 FAIL（当前级 `unknown` 未达目标级 `ob1`）。
仓库里其实已有零散的可观测性零件——桌面端 `@sentry/vue` 前端捕获、Gate 的
`POST /api/client/telemetry`、管理面 `/api/quota` 与 `/api/alerts`、以及
`docs/ops/TROUBLESHOOTING.md` 里的排查口径——但**没有任何一处声明**这四个维度
（metrics / tracing / logs / issues）归谁、落在哪、缺哪个。

这个状态的问题不是"缺功能"，而是**缺判断**：每轮治理审查都会重新发现同一个 FAIL，
后来的人分不清它是「有意暂缓」还是「忘了接」。要么接，要么显式不接，都得留痕。

## Decision

**可观测性四维本轮暂不接入**：不跑 `ponygo observe init`，声明维持缺失，`observe audit` 的
FAIL 作为已知缺口挂账。理由三条：

1. **没有遥测后端的落点与成本模型**。ob1 要求 metrics/tracing 有真实落点与查询面；本仓是
   自托管单机 + CF/Vercel 边缘 + 一台 VPS 的拼装形态，接四维前必须先定"存哪、谁查、谁付钱"，
   否则接出来的是一条没人查的管道（比不接更糟：多一处需要维护的假承诺）。
2. **现有证据面对排障够用，缺的是聚合不是采集**。事故定位目前靠
   `docs/ops/TROUBLESHOOTING.md` + 管理面配额/告警 + 客户端遥测端点 + 桌面端 Sentry 已能闭环
   （见 `docs/ops/stability-report-2026-09-29.md` 的取证口径）。真正缺的是跨组件聚合与
   SLI 视图，而那需要第 1 条的前置条件。
3. **时间经济性（P7）**。L2 门禁（决策格式门 / 凭据门 / 文档分层）刚落地，先把"承诺可验"
   这条主线稳定运行，再谈第二个治理维度；同时开两条战线最容易两条都做半截。

**边界（不做假声明）**：不写 `docs/observability.yaml`、不跑 `observe init`——
"未声明"是当前事实，用本条记录它，而不是用一个空声明把它伪装成已接入。

**重估触发条件（命中任一即立 ob1 提案，ADR 先行）**：

- 出现需要对外承诺的服务端 SLO（p95 / 错误率 / 可用性），届时必须有指标才能履约与举证；
- 线上事故复盘出现「缺少指标或链路导致无法定位」≥2 次（单次属噪声，重复才说明结构性缺失）；
- 出现常驻的 metrics/tracing 后端（自建或托管）且成本已获批——第 1 条的前置条件消失；
- 对外多租户商业化进入计费/对账阶段（届时 `gen_ai.*` 成本归因成为刚需）。

## Alternatives considered

- **直接接 ob1（metrics + tracing + logs + issues 全量）**：否决。没有后端宿主就接四维，
  等于先造管道后想用途；采集成本立刻发生，收益（可查询的 SLI）无法兑现，且会立刻产生
  「采样率/保留期/PII」三类没人有权决定的悬空问题。
- **只接 issues（Sentry 全栈，桌面端已有 SDK）**：看似最省，但会制造"已经接了可观测性"的
  假象——四维里接入一维却写 ob1 声明，是状态轴失真；若只做单维，也得先定 PII 与配额策略，
  那正是本轮缺的前置条件，不是省钱路径。
- **显式 opt-out（`docs/observability.yaml` 声明 off）**：否决。opt-out 表达的是"拒绝这套治理"，
  本仓是"暂缓"，语义不同；写 off 会让后来的人以为四维被明确否掉，而实际上重估条件一命中就要接。
- **不记录，继续留 `audit` FAIL**：否决。同一个 FAIL 在每轮审查里重复出现，最终所有人都学会
  忽略它（WARN/FAIL 免疫）——这比缺口本身更贵。

## Consequences

- `ponygo observe audit` 继续 FAIL（已知缺口，非回归）；`ponygo status` 的 L0–L2 判据不受影响。
- 新增任何观测能力（哪怕单个 span 或指标）时，先改本条并立 ob1 提案——不允许"顺手加埋点、
  不更新声明"，那会让本条从决策退化为过时文案。
- 重估条件里的第 2 条（事故复盘 ≥2 次因缺指标无法定位）要求复盘文档显式写"缺哪类证据"，
  否则永远凑不出计数——这是本条对 `docs/ops/` 的唯一附加要求。
- 本条的判据载体作用：它把"未接入"从默认状态变成**被记录的选择**，后续审查不必再从零论证。
