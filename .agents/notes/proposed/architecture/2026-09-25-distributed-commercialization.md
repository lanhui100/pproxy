# Agent Note: PProxy 自包含轻量多租户与分布式容灾架构

Status: proposed

## Problem
`pproxy` 当前仅支持单租户静态口令（`TUNNEL_TOKEN_HASH`）和单机 SQLite 存储，无法区分多用户身份、缺乏按流量计费与超额拦截能力；同时作为出海网关若单机部署存在单点故障风险。在国内公网部署 SaaS 存在未备案及电信合规风险，因此需要一套轻量自包含、零外部数据库依赖、能在国内机器（K3s 节点）与海外轻量 VPS（RackNerd）间自动组网容灾、并支持一键签发令牌与客户端直接显额的架构。

## Proposal
采用“非对称公钥验签 + 局部信用租约 (Credit Leases) + Tailscale 内网 Gossip 组网 + 签名防篡改零停机滚动升级”的去中心化架构：
1. **多租户与自包含 Token**：采用 Ed25519 签名，私钥仅保留在管理员本地离线控制端，线上各数据与代理节点仅持有公钥用于本地毫秒级验签（含 uid, quota, exp, max_conns=3）。
2. **防双花透支的信用租约**：将用户额度切分为节点局部 Credit Lease，节点仅在持有额度内放行流量，网络分区或用尽时强制 402 截断，消除跨洋延迟透支风险。
3. **节点一键 Join 与全景 Status**：通过单次有效（OTT）加入令牌，新节点通过一条命令加入集群，节点间在 Tailscale 内网运行基于 SWIM 状态机的 Gossip 心跳，支持任意节点秒级查询全集群健康大盘。
4. **防篡改滚动升级**：升级二进制强制校验 Ed25519 签名与 SHA256，Draining 阶段设定 15s 硬超时，支持从本地 P2P 流、MinIO 或 R2 冗余拉取。
5. **客户端系统级加固与生态**：macOS 动态探测出接口异步调用 networksetup 并落地崩溃快照自愈；402 触发桌面原生弹窗/通知，后台阶梯退避自愈；支持输出 Clash Meta 规范订阅及 `Subscription-Userinfo` 头部。

## Alternatives considered
1. **依赖集中式 PostgreSQL / Redis**：
   - *劣势*：污染现有服务器的其他业务数据库；集中 DB 成为单点故障，DB 宕机则全集群瘫痪；海外 VPS 跨洋直连国内 DB 延迟高且存在网络分区不可达风险。
   - *裁决*：否决。选择纯自包含内存 + 本地 SQLite + Ed25519 非对称公钥模型。
2. **对称密钥全网共享签发**：
   - *劣势*：在任意节点（如 512MB 的廉价海外 VPS）存储私钥，一旦 VPS 被攻陷，攻击者可自行签发无限额度 Token，系统彻底失控。
   - *裁决*：否决。选择离线/管理机保留私钥，线上节点仅持有验签公钥。
3. **基于全量累计流量的事后 Gossip 聚合**：
   - *劣势*：跨洋网络延迟（200~350ms）及丢包导致多节点并发时可轻松超额透支数倍流量（双花漏洞）。
   - *裁决*：否决。选择前置局部信用租约（Local Credit Lease）机制，将超额风险严格锁定在有界残值内。

## Acceptance criteria
1. 单元测试全绿（`cargo test --workspace` 无回归）；2026-09-25 联调实测 271 passed。
2. 安全拦截：伪造 Token、未签名升级二进制、网络分区下的超额并发必须 100% 被拦截。
3. 滚动升级：双节点高吞吐压测下触发滚动升级，客户端错误率为 0，网络不断。
4. 跨平台：Windows 11 与 macOS（含纯以太网设备）上系统代理与异常清理自愈正常。

## Risks
1. **跨洋网络分区**：当国内与海外 VPS 完全失联时，局部租约耗尽会导致海外节点提早进入 402，需在客户端合理配置备用节点切换策略。
2. **macOS 权限升级**：部分 macOS 机器在调用 `networksetup` 时若遇系统强安全策略可能会弹出密码确认框，需提供清晰的 UI 引导。
