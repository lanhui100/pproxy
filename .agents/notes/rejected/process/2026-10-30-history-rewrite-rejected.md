# Agent Note: 重写公共历史清除已失效 token（否决）

Status: rejected — 令牌已失效，重写会改写全部后续提交 SHA 并让仓内 ADR/账本引用的 sha 失效；收益低于成本

## Proposal

用 `git filter-repo --replace-text` 把 2026-09-29 引入的 5 个已失效 token 从全部历史 blob 中替换为 `<REDACTED>`，随后 `git push --force --all` + `--tags`，并用 GitHub API 清理悬空引用。

## Alternatives considered

- **立即重写并强推**：能彻底清除公共仓历史中的凭据字节。代价：影响面是 `55df3af` 之后的**每一条提交**——所有 SHA 变化，而仓内 `.agents/notes/`、`docs/`、`.dev-team/` 里大量决策记录以短 sha 互引（例：`5511e14`、`b7f1387`），重写后这些引用全部变成失效指针，`git log -S` 类审查证据也随之漂移；同时会打断任何已有克隆/分支/PR。收益（失效凭据的字节）与成本（整棵历史与引用面）不成比例。
- **只删文件、保留其他提交**：`filter-repo --path` 删除同样触发整链 SHA 重写，成本与上一条相同，而凭据仍可能出现在这些文件的旧内容里（日志 txt 曾含 token），并不更干净。
- **等待 GitHub 秘密扫描/仓库转私有**：不改历史，靠平台能力降低暴露；若未来要开源复用，可再评估。
- **不做任何处理**（采纳）：token 已经用户确认失效（`.dev-team/governance-state.json` 与 2026-10-30 审查报告登记），当前树 `git grep` 0 命中；残留只存在于历史字节，攻击价值为零。以「不重写」作为常态，并在每次审计报告中如实声明。
- **重写后建立 SHA 映射表**：能缓解引用失效，但映射表本身要长期维护，且外部克隆拿到的仍是旧历史；复杂度不划算。

## Risks

- 公共仓历史里仍可检索到 5 个已失效 token 的字面值（`e0acfe3` 之前的提交）；任何人拉到旧提交都能看到。缓解：令牌已作废；`secret-scan` 默认阻断 HEAD 残留（`SKIP_HISTORY=1` 才会降级）。
- 若未来发现令牌实际仍有效（误判失效），本决策必须重开：改为立即轮换 + 重写历史。
- 触发重估的条件：① 仓库转为多人协作或引入外部贡献者；② 历史中出现**非**已失效凭据；③ GitHub 通知该仓被 secret scanning 命中且要求处置。
