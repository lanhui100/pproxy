# pg-doc-hygiene —— 文档家、契约与推理泄漏

文档卫生的三件事：**事实有唯一可寻址的家**、**契约不丢命题**、**读者视点在 HEAD 而不在作者会话里**。
本技能只给判断与流程，不替代项目的机械门禁。

**项目等价命令约定**：文中 `<项目文档门禁命令>`、`<项目检索命令>`（例 `rg -n`）、
`<项目配对重录命令>`、`<项目词数/规模门禁命令>` 按被安装项目真实入口替换；替换后写进报告。

## 真相源

- 项目的**文档标准**（tier 分类法、写作规则、slop 清单）——文档规则的家就是它，不在别处复制第二份。
- 决策记录规则（`notes/README.md` 之类）——理由与历史叙事的合法去处。
- 各载体的既有契约：根常载文件、模块/包 README、生成参考的再生成器、双语配对与词数预算的门禁脚本。

## 步骤

1. **定 scope 并定排除**：缺 scope 就报"需要 scope"并停下，不推断全仓。默认排除第三方目录（`vendor/` 等）
   与**冻结归档区**（只读史，不据此判现行，也永不修它的出链）。排除项写在包含项之**后**，
   否则后加的包含规则会把它们放回来。
2. **定位：一个事实一个家**。按 job 分家，而不是按"谁先写到"：

   | 事实的 job | 家 |
   |---|---|
   | 每次会话必载的常驻约定（短条文 + 链到理由层） | 根常载文件 |
   | tier 分类 / 写作规则 / slop 清单 | 文档标准 |
   | 组合、核心模块、接缝、扩展点（有序地图） | 架构地图 |
   | 为什么这样 / 为什么不那样 | 决策记录（含 Alternatives） |
   | 单模块的配置/语义/限制/扩展点 | 该模块或包的 README |
   | 带编号验证步的操作指引 | how-to |
   | bug 年表、证据、因果链、预防 | 事故复盘 |
   | 交付过程证据（已完成的 spec/task/review） | 过程记录区 |
   | 从源再生成 + 新鲜度门禁 | 生成参考 |

   速查：bug→复盘；理由→决策记录；过程→how-to；契约→模块 README；常驻→根文件；交付证据→过程记录。
   同一条规则出现两处 → 用特色短语 `<项目检索命令>` 找出来，留一家、其余链过去。
3. **事实核查（先跑再说）**：文档陈述的是"今天怎么行为"，操作类主张唯一的合法证据是**亲自跑过**。
   逐条执行文中将出现的命令/片段/示例，只写观察到的输出、告警与失败模式；
   依赖你没有的凭据或网络的，明说并指名验证 owner，而不是断言。
   改旧页先与最新主干对比：主干上的陈旧陈述照样是错的——按代码改，不按旧散文改。
   复现不了的命令、字段、默认值、行为：删掉，不要从记忆或邻模块 README 搬。
4. **契约完整性（这是"不许删"的清单）**：动笔前先把段落里的命题列出来，逐条判定是否前后都在场——
   **主体与动作、条件/时序/顺序、模态（必须/可以/永不）、负向保证与例外、归属、副作用、失败模式与后果**。
   删修饰、删重复、删叙事，只有当每个事实子句都活下来且更清楚时才算改进；**词数变少不是改进**。
   架构、理由、算法、历史、扩展例子 → 激进外链到它的家；调用方/维护者就地需要的契约（行为、失败、归属、后果）→ 留在使用点。
   生成物（清单、快照、夹具）是派生物：先改拥有它的源或场景，再重生成；不要手改派生物。
5. **按载体补必写、避必不写**：公共 API 文档写调用方可见的返回区分、抛错/拒绝、副作用、归属、时序、取消、持久性；
   内部注释写代码表达不出的不变量、竞态顺序、安全边界、反常失败，**不写控制流复述**；
   模块注释写角色、依赖、职责与非显然架构选择；测试注释只写非显然设计（为何这个夹具/断言/平台让步/真实入口是必要的）；
   模块 README 写配置、语义、失败、限制、扩展点与对外可见效果；决策记录留独有理由、机制、备选、后果与已交付证据；
   复盘留年表、证据、因果、影响与预防；技能与 agent 指引留行为护栏与显式范围限定（"指引，不是脚本"）；
   诊断消息点名失败主体、被违反的规则与修法。面向用户/模型的串按"措辞即行为"处理，须有拥有它的行为证据才改。
6. **CoT 泄漏（chain-of-thought，推理转录外泄到成品散文）：一个测试 + 八类类型学**。测试只有一句：**HEAD 上的读者，没有任何会话转录、PR 讨论或未提交
   草稿，能否解析每个引用并验证每个主张？** 不能 → 把幸存事实改写成仓库视点，删掉转录；能 → 它不是泄漏，
   但在 README/文档/JSDoc 这类"当前态"载体上，可解析的变更故事仍是变更叙事，应路由到决策记录。
   八类：① 已死的设计会话语引用——`(decision 7)`、`(audit C2)`、`plan §1.4`、阶段标签（`T4`/`W3`）、
   "设计台账"；有已提交的 owner 就按名与路径引用，否则删引用、把事实子句改成自足陈述。
   ② 栈与 PR 视点——"本栈后面的 PR"、"本 PR 新增"。改成机制陈述或扩展点；延后工作进 `TODO` 或 issue。
   ③ 变更叙事与版本戳——"原来是"、"不再"、"旧 X"、"这一稿"、"现在"。写当前行为；
   已修的回归写成现在时反事实（"没有 X 就会 Y"），不写成仓库史（"原来会 Y"）。
   ④ 评审编排——"评审中被否"、"评审者确认"、草稿序号。留下决定与理由，删掉谁在哪一轮说的。
   ⑤ 对评审者辩解——"这是安全的，因为它只是…"。写使代码安全的不变量，或直接删。
   ⑥ 复述与推导转录——控制流旁白（"先 X 再 Y"）、测试走查、显然分支的证明。删；只留非显然契约。
   ⑦ 对冲与计划残留——"目前大概够用"、无标记的延后。升级为 `TODO`/`FIXME` 或写出真实上界。
   ⑧ 作者语言滑落——正文语种里混入未翻译的工序词或私有分隔符。翻译或删。
7. **不是泄漏的保留清单**（删多和删少都错，按此执行）：issue 引用（`#1470`、`TODO(name):`）；
   决策记录与复盘里的已合并 PR/issue 引用（那是被许可的证据）；抑制/忽略理由注释（理由错就修，不删）；
   现在时反事实回归钉（"没有 X 就会 Y"）；实测边界（`measured:` 这类证据词是承重的）；运行时新旧态
   （"旧连接排空后新连接才接入"是生命周期，不是变更史）；按设计在仓外解析的外部引用（标准号、设计稿名）；
   项目口吻的"我们"与决策记录的"备选"节。

## 校准样例

- 正例（放置）：`setTimeout` 上限从 10s 调到 30s 的**理由** → 决策记录；30s 这个**当前值** → 模块 README。
  反例：把理由写进模块 README，把值抄进根常载文件——两处都会漂移。
- 正例（去叙事留事实）：`// 原来用 10s，现在 30s` → `// 上限 30s：更长的等待会被网关先断开`。
  反例：留下"原来/现在"对——读者在 HEAD 上无从验证过去。
- 反例（已死引用）：`// 见 design §4.7 与 decision 7`——两者都没提交，读者无法解析；改成自足陈述或链接到已提交的决策记录。
- 正例（保留引用）：`// 见 #1470` 与 `// oxlint-disable-next-line … -- 生成代码不满足该规则` 都必须在场。
  反例：为了"清理叙事"把 issue 引用和抑制理由一起删掉。
- 反例（对评审者辩解）：`// 这里不安全，但调用方总是传字符串` → 要么写进类型/守卫，要么写出不变量；辩解不是契约。
- 正例（运行时新旧态不是变更史）：`// 旧连接排空后，新监听才开始接受` 保留。
  反例（版本戳）：`// v2 新增的接受顺序` → 改成机制陈述。
- 正例（实测边界）：`// 嵌套上限 512：measured ≈0.15s` 保留证据词。
  反例：删掉 `measured` 只剩数字，读者无法判断这是规范还是观测。
- 反例（手改生成物）：直接编辑生成清单或配对 sidecar——下次重生成即回滚，且掩盖了真源未改。
- 边界（靠 review）：一句话既像克制又确实丢了"永不"模态——判据是命题是否完整，不是语感。

## 验证与报告

- 跑本项目机械门禁：`<项目文档门禁命令>`（链接、格式、配对、预算、技能元数据；名称按项目替换）、
  `<项目词数/规模门禁命令>`、`git diff --check`；改了双语或配对页则用 `<项目配对重录命令>` 重录，别手改 sidecar。
- 复扫：重跑泄漏探针（含隐藏目录），期望**只剩**许可保留类、本技能自身目录与被引用的原始证据；
  再逐条确认保留下来的每个引用在 HEAD 可解析。
- 报告：巡检范围（及排除项）、明确改动、**刻意保留**、延后项、实际跑过的命令与结果。
  不得把未执行的搜索称为穷尽；不得在没有拥有该行为的证据时改动面向用户/模型的措辞。
