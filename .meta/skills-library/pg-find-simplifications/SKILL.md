# pg-find-simplifications —— 有证据的简化勘探

简化 = 去掉**被持续维护的义务**：API、表示、生命周期状态、配置路径、依赖、测试、文档。
宁可少数几条证据扎实的候选，不要一份"删了多少行"的清单。这是判断指引，不是勾选表。

**项目等价命令约定**：文中 `<项目检索命令>`（例 `rg -n`，无则用 `grep -rn`）、
`<项目测试命令>`、`<项目类型检查命令>`、`<项目文档门禁命令>` 按被安装项目的真实入口替换。

## 真相源

- 根常载约定 + 架构地图 + 防御模式/测试策略文档 —— 判断"这是义务还是意外"的底。
- **活动**决策记录（proposed/implemented/rejected）—— 刻意的设计不要当垃圾。
  冻结归档区只作历史示例：不据它判现行，也永不修它的出链。
- 既有依赖与语言标准库 —— 替换基础设施前先搜，不然是"换个地方写同样代码"。

## 步骤

1. **定范围与约束**：读上面四类真相源，写下本次范围（模块/包/文档面）与明确排除项。
   范围宽时按正交域分派：核心循环与持久化 / 装配与注册 / 对外接口与 SDK / 子进程与执行提供者 /
   组合与脚本与测试与文档。每个子域都要求"消费者证据 + 已否决的替代"。
   **受保护设计先划出来**：刻意的双实现、接缝抽象、树上提供者支持——除非用户显式推翻，不提案删除；
   但受保护设计内部的未用成员仍是候选（只要删除不损其目的）。
2. **六问发现**（逐候选问，答案决定是否继续）：
   - 声明的特性有**完整效果路径**吗？追生产者→转换→提供端支持→可观察结果。遍地复制的字段
     可能没有写入者、没有读者，或只有"拒绝它"的实现。别只搜调用点，也搜构造器与判别式发射点。
   - 哪些区分真的改变消费者的动作？控制授权/驻留/持久性/归属的内部区分要留；
     只制造"不可用的选择"的公开区分可以收。
   - 更小的显式行为能消灭整个子系统吗？固定间隔、调用方自报时区、显式失败上报，
     可以抵掉通用日历、持久化默认值、自动回滚。**点名放弃的能力**，别只说删了什么。
     已有生产调用方时这是行为决策，不是自动否决。
   - 消费者能否在需要时读到权威值？抄写的历史、晋升台账、"失效事件 + 再读"、并列于共享投影流的缓存
     ——先确定所需观测时点，再判能否用派生/复用一并删掉订阅、留存数据、陈旧响应处理与恢复路径。
   - 组合是否被误当策略？可选服务在场、提供者方法、兄弟工具都能表达"可用性"，却不必决定部署行为。
     显式配置或调用方意图操作可删注册表与依赖检查；归属或完成时序不同的操作要保留。
   - **谁承担完整维护成本**？透传配置、重复的应用树、产品在用的演示启动器、只做解析的工作区、
     自带升级生命周期的安装辅助——把被删系统与替代方案整体比较，含残余胶水。
     把复杂度搬家、或加一道门禁让两份定义保持相等，都不算简化。
3. **证明可达性与取舍**：先 `<项目检索命令>` 再读命中，搜确切符号、属性读写、判别值、事件与线协议
   字符串、配置键、模块名，以及 `.method(` 与 `method(` 两种形态。
   测试与声明只能证明契约，不能证明有已发布的生产者或消费者。
   按**实际入口**而不是目录名给样例/夹具分类；跟随生成清单到它的消费者：
   被模型或用户写的插件挂载所消费的清单是动态产品 API，只在文档里列一次的清单不是固定调用点。
   公开的第三方扩展路径可以是有意零调用点。
4. **逐个候选记录证据链四件套**（缺一件即降级为"证据不足"）：
   ① **owner**（当前谁拥有这段契约/状态）；② **producer/consumer 路径**（产出点 → 消费点）；
   ③ **消失清单 vs 保留清单**（一起消失的文件/测试/文档/注释；必须留下的残余行为）；
   ④ **最强反方**（保留它的最强理由）。据此归类：
   删除不可达或无人读取的行为 / 收窄公开或产品行为并**显式说明损失** / 保留为受保护义务或证据不足。
5. **归属与失败语义不许被顺手抹平**：对复制、冻结、校验、回调捕获，点名值的来源、下一归属者、信任边界。
   同进程的类型化调用通常借用只读值；解析器、配置加载、队列、模型/工具 JSON、持久文件、worker、
   进程、线协议解码器则拥有或校验其输入。"敌意 getter"或"回调替换"测试本身不构成需求；
   冻结根不证明后代不可变；id 相等不证明对象同一。异步机制里把每个 promise、标志、取消路径、
   disposer（清理函数）、预留映射到归属与状态迁移；只有在表达同一事实时才合并。同步发布与回滚、回调收敛、
   首个终态仲裁、worker/进程归属、dispose 到静默，都属必须保留的语义。
   能记录真实事实的持久起止标记，不因渲染器忽略就可删——丢掉被中断的工作是能力损失。
6. **替换基础设施只为净减**：先查既有依赖与标准库；列出被删除的确切实现与专属测试、维护与传递成本、
   胶水必须保留的每一处行为。演练最可能击败替换的不匹配：协议截断、取消与清理、配置上限、
   确定性测试时钟、平台打包、源码入口与构建入口的差异。
   "覆盖了帧格式但为了限长又要重写一遍帧格式"的库不是简化。被接受的边缘行为变更写进提案与对应测试；
   不要只证明依赖的通用规格，却漏掉本项目专属胶水的测试。
7. **落地记录**：实质提案用固定骨架 `Problem` / `Proposal` / `Alternatives considered` /
   `Acceptance criteria` / `Risks`，含消费者证据、被删的维护成本、放弃的能力、可观察的验收条件；
   已实施的决策换成已实施骨架。同一决策已有 owner → 更新而不新建重复记录（别为凑候选数造条）。
   新记录必须做一次**限定范围**的取代检查（同决策/同机制/同被否替代），别顺手全树审计。
   小而局部的改进写成就地 `TODO`/`FIXME`/`XXX` 并注明紧迫理由，不立设计记录。

## 校准样例

- 正例（不可达删除）：某配置项 `retryWindowMs` 只在类型声明与示例配置里出现，无解析分支无读取点
  → owner=配置 schema；消失清单=字段+示例+校验用例；保留清单=相邻重试次数键；反方"外部用户可能写过" →
  先查无兼容读路径，再删并记一条决策。
- 反例（伪简化）：把两份"看起来一样"的适配层合并成一个，代价是给剩余一个加两个布尔开关——
  复杂度搬家 + 新增分支，义务没减。
- 反例（拿测试当需求）：为一个函数写过的"敌意 getter"测试被当作"必须保留防御拷贝"的证据；
  真实调用方是同进程只读传参，测试造出的是不存在的场景。
- 正例（收窄公开面）：三个内部状态映射到一个对外状态，内部区分保留（它控制授权），
  公开枚举删掉两个永远不可选的值 → 显式写出"放弃的是调用方的可观测粒度"。
- 正例（能力换机制）：把通用日历与持久化默认时区换成"调用方必须传时区"，删掉整条回滚与迁移路径 →
  在提案里点名放弃"缺省时区"能力，并把拒绝路径写进验收条件。
- 反例（只搬复杂度）：引入依赖替换手写解析，但为了对齐边缘行为又在自己代码里重实现一整套边界处理，
  并新增一门禁"保证两份定义相等"。
- 反例（越权实施）：用户要"勘探报告"，却直接提交了删除补丁——调查不是许可；实施须在授权范围内。
- 边界（靠 review）：受保护的双实现内部的未用成员——留还是删，取决于删除是否损及其存在目的。

## 验证与报告

- 每个入选候选：四件套 + 归类（删除不可达 / 收窄并声明损失 / 保留义务或证据不足）+ 若实施则给验收条件。
- 报告要含**有意义的否决与延后**，以及拟新增/合并/保留/删除的决策记录条数——只报候选数是在报工作量，不是结论。
- 实施后跑：`<项目测试命令> <受影响测试>`、`<项目类型检查命令>`；若动了文档或注释，再跑
  `<项目文档门禁命令>` 与 `git diff --check`。删除前按"删代码前先搜消费者"确认零生产消费者，
  验收 = 搜索零残留 + 门禁照常绿。
- 不得把未验证的搜索称为"穷尽"；范围仍在扩张时用草稿态交付，并列出尚未勘探的域。
