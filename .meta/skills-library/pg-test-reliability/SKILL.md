# pg-test-reliability —— 并发与清理下的可靠测试

测试要能在项目的**真实 CI 拓扑**下成立，而不只在安静的开发机上单跑成立。
本技能拥有隔离与可靠性判断；它不替代项目的测试分层策略，也不负责挑推送前的命令清单。

**项目等价命令约定**：文中 `<项目测试命令>`、`<测试运行器并发参数>`、`<项目类型检查命令>`
按被安装项目的真实入口替换（读任务脚本/包清单/CI 配置确定），替换后写进报告。

## 真相源

- 项目的测试策略文档 —— 单元 / 覆盖率 / 期望输出 / 快照 / 浏览器 / 真实外部依赖各层选谁。
- 项目的防御模式文档 —— 生命周期、子进程、取消、清理的既有约定。
- 测试运行器配置与 CI 工作流 —— worker 数、作业切分、共享主机事实（决定叠加层数）。
- 录制型场景的夹具说明 —— 若项目有"录制/回放"目录，它有自己的摆放与命名规则。

## 步骤

1. **建模执行拓扑**（除非现行配置证明不会，否则假定这些层会重叠）：
   ① 同一测试文件内的用例；② 不同文件或 worker 进程；③ 同一作业里的独立运行器/门禁进程；
   ④ 共享同一主机的不同 CI 作业。**进程隔离不隔离主机端口、可预测文件系统路径、外部服务、
   数据库、socket、被继承的子进程。** 对每个被占用的资源写清：owner、原子分配机制、可观测的就绪信号、
   已注册的清理、静默完成信号。
2. **不要用"整包串行"掩盖单个夹具的缺失隔离**：先缩小独占作用域或改资源分配方式。
   一个串行块保护不了被另一个文件、进程、作业或主机拿走的主机资源。
3. **原子分配**：用资源 owner 自己的分配器，而不是"先探测可用、稍后再占"。
   网络夹具绑回环的临时端口（`listen(0)`）并在服务报告"正在监听"后读实际地址——**永不先扫空闲端口再绑**；
   每用例私有临时根用 `mkdtemp`，不占可预测共享路径；数据库/socket/会话/输出位置给唯一命名空间；
   必须先不存在才能创建的场景用独占创建；把**稳定录制标识**与**临时传输地址**分开，在夹具内做翻译，
   而不是逼活资源去迁就录制值。仅作解析输入或期望值的字面路径/URL 不是被占用资源，不要因为"看起来是硬编码"就改。
4. **容纳进程全局状态**：`process.env`、`cwd`、假时钟、locale 与时区、模块 mock、注册表、console 钩子、
   `globalThis`、全局请求拦截，都当**独占可变资源**。优先依赖注入或实例级适配器；必须变更时：
   记录原值是"不存在"还是"存在"、精确还原该状态、立即注册还原、把变更包在最小 `try/finally` 作用域、
   在"局部 finally 之前也可能失败"时加 `afterEach` 兜底、只拦截夹具真正拥有的那一次调用。
5. **尊重平台语义**：同一套件常在两类操作系统上跑，平台拥有的值不一定原样回来。
   把值写回去只有在断言**容忍写回失败**时才安全——用还原证明"指纹会失效"到处成立，
   用还原证明"记录仍有效"就默认了无损往返（某些文件系统的时间戳精度并不给回原值）；
   断言依赖还原值时，从**重新读取**取值而不是取记忆值。
   环境变量名大小写不敏感的平台上，`http_proxy` 与 `HTTP_PROXY` 是两个键但只有一个条目；
   句柄异步释放的平台上，rename/删除需要按实际竞争程度给**有界重试**；没有 POSIX 权限/信号语义时，
   用**显式平台跳过并写明理由**，而不是把断言在全平台弱化。优先选"处处成立"的观测方式。
6. **超时预算对照车道**：用例级超时会**覆盖**运行器默认值而不是让位于它——低于车道预算的值等于
   擅自缩减 CI 已给的时间，而同一个字面值在默认更小的主机上又是放宽。受进程创建约束的套件取车道预算；
   更紧的值必须带"为什么更紧"。hook（setup/teardown）预算随用例预算一起抬：清理同样承担竞争压力，
   只抬用例预算只是把竞争失败挪进 teardown。当**超时本身是被测对象**时，外层等待要远大于被测超时，
   否则负载而非产品决定谁先触发。
7. **在状态上同步**：固定 sleep 不是"setup 完成"或"清理结束"的证据。
   等显式就绪事件、握手、状态迁移、拥有的 promise 或外部可观察条件；用 deferred/屏障把竞态放在确定点，
   以证明相关操作真的重叠；超时只用于给等待定上界，绝不用来让断言成立；
   除非调度顺序本身就是被测的产品行为，否则不要断言依赖调度器的顺序；时间是被测对象时注入或伪造时钟，
   并在结束时恢复真时钟。
8. **清理到静默**：acquire 之后**立刻**注册清理，使断言失败也释放资源。清理要：停止新的回调/请求、
   解绑监听、还原全局钩子、终止自己拥有的工作，并**等待**子进程退出、服务关闭、worker 终止等等价完成信号。
   只调 `abort()`/`close()`/`kill()` 而不等完成信号 = 不完整清理；迟到完成可能污染其他用例时，
   要证明清理确实阻止了它。
9. **证明预期回归**：能先看到普通回归在修复前失败；新静态/语料守卫先临时注入被拒样本、观察预期失败；
   竞态用屏障证明重叠（重复执行不等于竞态测试）；端口/socket/共享路径/子进程等主机资源，
   在"跨进程隔离正是修复内容"时**并发跑独立测试进程**；夹具自带 deadline 时，先断言没有信号或超时先结束了子进程，
   再断言退出码，否则被杀的子进程会伪装成"状态不匹配"；验证外部状态、事件、文件、日志、退出与清理，
   而不是相信组件的自我报告。压力跑是补充，不是替代。
10. **拒绝掩盖型修复**（不要把下列当根因修复交付）：没搞清在等什么就加超时；加重试；把全部文件串行；
    吞掉错误或未处理的拒绝；弱化断言；把不稳定行为归一化掉；在清理或断言前加 sleep。
    例外仅在"外部提供者瞬时失败且已有文档化策略"的边界上保留有界重试；**把预算恢复到车道原本给的值
    不算掩盖**——但它必须点名在等哪段工作。

## 校准样例

- 正例（原子分配）：`server.listen(0)` 后从 `server.address()` 读端口，并等 `'listening'` 再连。
  反例（TOCTOU）：先扫一个"好像空闲"的端口写进常量，再在用例里绑定——另一进程可能已占用。
- 正例（全局态）：保存"原值是否存在"的哨兵，`finally` 里用它决定 delete 还是还原。
  反例：把 `process.env.X = ''` 当作"未设置"，下游的空串分支因此进入不同逻辑。
- 正例（平台）：把 mtime 写回只为证明指纹会失效；断言"记录仍有效"时改用重新读取的值。
  反例：断言写回的 mtime 与记忆值相等——在时间戳精度受限的文件系统上偶发失败。
- 正例（超时）：用例证明 20ms 的上限会触发，外层等待取秒级车道预算。
  反例：外层等待 50ms —— 负载决定是"上限先到"还是"外层先超时"，失败信息会指向错误的地方。
- 正例（清理）：等待子进程 `'exit'` 事件后断言退出码，并先断言无信号/无超时先结束。
  反例：`kill()` 之后立刻断言退出码——被杀与业务失败无法区分。
- 反例（掩盖）：CI 偶发失败后把用例重试 3 次、超时从 5s 提到 60s——两个改动都没说出在等什么状态。
  正例（真正的修复）：发现夹具读的是"文件存在"而不是"内容写完后关闭"，改为等写入方的完成信号。
- 反例（整包串行）：把整个套件 `sequence` 化以避免端口冲突——另一个 CI 作业仍在同一主机上抢端口。
- 边界（靠 review）：真的只有外部提供者才会瞬断时，有界重试可否保留——判据是该失败是否属于本项目可控的确定性行为。

## 验证与报告

- 先跑受影响行为的**最窄聚焦回归**：`<项目测试命令> <目标文件或用例名>`，确认选中用例数不为 0。
- 只有变更确实拥有该风险时，才追加拓扑证据：全局变更→还原证据；生命周期/子进程→静默清理证据；
  端口/socket/共享路径→并发独立进程证据；新守卫→负样本对照（红相）。
- 报告里写**确切命令与观察到的结果**（含退出码与关键断言输出）。
- 术语只允许三档：通过 / 失败 / 待定。不得把重试后通过、被跳过的用例、仍 pending 的 CI 描述成通过。
- 若结论是"这是既有 flaky，不是本次引入"，必须给出证据链（失败点、竞争资源、复现条件），而不是概率陈述。
