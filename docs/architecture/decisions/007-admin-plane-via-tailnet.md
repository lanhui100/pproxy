# ADR-007: 管理面远程通道采用 tailnet（公网化记为未来拓展）

- 状态: 已接受 | 日期: 2026-08-22

## 背景

M5 Windows GUI 需要消费管理面 API，但管理面自 M1 起仅绑 `127.0.0.1`（ADR 边界内正确：当时唯一管理工具是本机 curl/pony）。GUI 运行在另一台机器上，必须为其修一条受控通道。

候选：tailnet 直连 / SSH 隧道 / 管理面公网化（复用 M4 CF Tunnel）/ LAN 直绑+防火墙白名单。关键不对称性：数据面泄露 pony token ≈ 白嫖流量；**管理面泄露 admin token = 整个网关易主**——通道选型按最敏感 API 的暴露面最小化原则裁决。

## 决策

**管理面远程通道采用 tailnet 承载**：

- 服务端以环境变量重绑监听地址（`PPROXY_LISTEN_ADMIN=<tailnet-ip>:8900`，代码已支持，一行 unit 改动，可逆）；本机进程经 tailnet IP 自访不受影响
- Windows 端入网 tailnet 后 GUI 直连，Settings 页填一次稳定地址
- 信任边界从"本机进程"扩至"自有设备集 + admin token"双重门槛；流量 WireGuard 加密
- 架构文档边界同步修订：tailnet 作为**管理面正式依赖**写入拓扑；M4 裁决不变——**数据面公网入口仍走 CF Tunnel**

**否决/搁置记录**：

- SSH 隧道（TECH_DESIGN 原案）作为备选保留：零服务端改动但隧道生命周期体验差（断线重连、休眠恢复），对日常使用的桌面工具摩擦过大
- LAN 直绑+防火墙白名单否决：防火墙规则属"静默失效型"防护，且出门场景仍需叠加其他通道
- **管理面公网化记为未来拓展**（非当前路线）：若未来出现高频不可信网络管理需求，重启评估时**前置条件为 CF Access 身份验证 + 限速补齐（P1 缺口关闭）**，不接受裸 Bearer 上公网

## 后果

- ✅ 管理面暴露面数学最优（自有设备集），零新增端口、零公网面
- ✅ 在家/在外行为一致，GUI 无隧道生命周期管理负担
- ⚠️ tailscaled 故障时管理面不可达（数据面不受影响；systemd 自动拉起缓解）
- ⚠️ 引入对 Tailscale control plane 的间接依赖（登录/协调面）；断网已入网设备间直连通常仍可用
